# სტატიების მართვის მოკლე გზამკვლევი

ადმინი: `http://localhost:31997/admin/posts`. ახალი ჩვეულებრივი სტატიის შექმნა
არ საჭიროებს HTML-ს, JSON-ს, JSX-ს ან კოდის შეცვლას.

## ახალი სტატია

1. გახსენით **სტატიები → ახალი სტატია**. შეავსეთ მთავარი სათაური. მისამართი
   ქართულიდან ლათინურად ავტომატურად იქმნება; შენახვამდე მისი ხელით შეცვლა შეგიძლიათ.
   შენახული მისამართი აღარ იცვლება. დამატებითი ბმული მოგვიანებით alias-ით დაამატეთ.
2. მიუთითეთ ავტორი, კატეგორია და მოკლე აღწერა. ტექსტის ბლოკის ხელსაწყოებით დაამატეთ
   აბზაცები, სათაურები, გამუქება, სიები, ბმულები, ცხრილები და არსებული პანელები.
3. აირჩიეთ სტატიის განლაგება. ჩვეულებრივი სტატიებისთვის ხელმისაწვდომია
   სტანდარტული და კლასიკური განლაგებები. არსებული ოთხი სტატია თავის დამტკიცებულ
   განლაგებასა და სექციების თანმიმდევრობას ინარჩუნებს.
4. ქვედა მუდმივი ზოლიდან შეინახეთ **მონახაზი**. გახსენით **შენახული მონახაზის
   წინასწარი ნახვა**. პრევიუ მხოლოდ ავტორიზებულ მომხმარებელს აქვს და ქეშში არ ინახება.
5. შეამოწმეთ ტექსტი, წყაროები, გრაფიკები და მობილური ხედი, შემდეგ დააჭირეთ
   **გამოქვეყნება**. სტატია ავტომატურად გამოჩნდება ბლოგში, რეკომენდაციებში და,
   თარიღის მიხედვით, მთავარი გვერდის ბოლო სამ სტატიაში.

ჩვეულებრივ ტექსტურ ველში Enter მონახაზს ინახავს. გამოქვეყნება და გამოქვეყნების
გაუქმება შესაბამისი ღილაკით ცალსახად აირჩიეთ.

## სურათები, კვლევა და წყაროები

- **მთავარი სურათი**: ატვირთეთ ფოტო, მიუთითეთ ალტერნატიული ტექსტი და აირჩიეთ
  მოჭრის პარამეტრი. მოჭრა სტანდარტული სტატიის მთავარ ფოტოზე გამოიყენება;
  არსებული ბარათებისა და დაცული მთავარი სურათების ფორმა უცვლელია.
- **სურათის ატვირთვა** ან **სურათი ბიბლიოთეკიდან** ქმნის ტექსტში სურათის ბლოკს.
  მიუთითეთ განლაგება, პროცენტული სიგანე, პიქსელური პროპორცია, ალტერნატიული ტექსტი,
  წარწერა, უფლებების/ავტორის მითითება და წყაროს ბმული.
- **კვლევის სექციის დამატება** აერთიანებს განმარტებით ტექსტსა და გრაფიკს.
  აირჩიეთ მარცხენა ან მარჯვენა მდებარეობა. თავისუფალი კომპონენტის სიგანე შეიძლება
  იყოს 10–100%; პატარა ეკრანზე სურათი/კომპონენტი სექციის სრულ სიგანეს იკავებს.
- **კომპონენტის დამატება** აჩვენებს რეგისტრირებულ არჩევანს და შიდა პრევიუს.
  SVG გრაფიკისთვის აირჩიეთ დამტკიცებული გრაფიკი; ინტერაქტიული შედარებისთვის
  შეავსეთ სათაური, ერთეული და მაჩვენებლები. დაამატეთ ტექსტური აღწერა და წარწერა.
  ტექნიკური ID და ვერსია ცალკე გასახსნელ ინფორმაციაშია.
- **წყაროს დამატება**: მიუთითეთ სათაური, ბმული და ბიბლიოგრაფიული აღწერა.
  შესაბამის ბლოკში მონიშნეთ ეს წყარო ან გამოიყენეთ **წყაროს ჩასმა**.

შიდა პრევიუ წარმოადგენს კომპონენტს; სრული სტატიის პრევიუ ამოწმებს საბოლოო
ზომას, წყაროებსა და მეზობელ ტექსტთან განლაგებას. არასრული კომპონენტი აჩვენებს
შეტყობინებას და სტატიის სხვა ველებს არ აზიანებს. შენახვასა და გამოქვეყნებას
სერვერული ვალიდაცია ამოწმებს. არასასურველი სკრიპტის, JSX-ის, MDX-ის ან SVG-ის
ატვირთვა რედაქტორიდან დაუშვებელია.

## არსებული სტატია და ვერსიები

გახსენით სტატია სიიდან. **მონახაზის შენახვა** საჯარო ვერსიას არ ცვლის.
ცვლილებების გამოსაჩენად კვლავ საჭიროა **გამოქვეყნება**. პირველი გამოქვეყნების
თარიღი რჩება უცვლელი — რედაქტირება სტატიას ხელოვნურად არ გადააქვს სიის თავში.

**ვერსიების ისტორიაში** შეარჩიეთ ძველი ვერსია და ნახეთ მისი პირადი პრევიუ.
**ვერსიის მონახაზად აღდგენა** ქმნის ახალ მონახაზს; ის მხოლოდ ცალკე გამოქვეყნების
შემდეგ ხდება საჯარო. ისტორიული HTML არქივად ინახება და ვერ ჩაანაცვლებს აუცილებელ
დაცულ განლაგებას ავტომატურად.

**გამოქვეყნების გაუქმება** სტატიას საჯარო URL-იდან, ბლოგიდან, მთავარი გვერდიდან
და რეკომენდაციებიდან ხსნის; ტექსტი და ისტორია ბაზაში რჩება. განმეორებითი
გამოქვეყნება თავდაპირველ თარიღს ინარჩუნებს. „რა არის TM?“ აუცილებელი evergreen
გვერდია: არ შედის ქრონოლოგიურ სიაში და დაცულია წაშლისა და გამოქვეყნების გაუქმებისგან.

თუ სხვა ფანჯარაში ცვლილება შეინახეს, მიიღებთ კონფლიქტის შეტყობინებას.
შეინარჩუნეთ თქვენი შეუნახავი ტექსტი და გვერდი განაახლეთ; სხვისი ვერსია ჩუმად
არ გადაიწერება. დამატებითი მისამართის შექმნამდე მონახაზი შეინახეთ. Alias საჯარო
სტატიაზე მუდმივად გადამისამართდება და გამოუქვეყნებელი სტატიისთვის 404-ს აბრუნებს.

## დეველოპერისთვის: ახალი ვიზუალური კომპონენტი

ჩვეულებრივი სურათები ადმინიდან იტვირთება. სპეციალიზებული SVG/React/ინტერაქტიული
კომპონენტი ჯერ დეველოპერმა უნდა შექმნას და დაარეგისტრიროს:

1. სტატიკური SVG შეინახეთ `apps/web/public/images/`-ში ახალი, ვერსირებული სახელით.
   გადაამოწმეთ, რომ არ შეიცავს სკრიპტს, event handler-ს, `foreignObject`-ს ან გარე
   ჩამოტვირთვად კოდს. უკვე გამოქვეყნებული ფაილის შეცვლის ნაცვლად შექმენით ახალი
   ფაილი/asset ID. `src/lib/articles/visual-assets.ts`-ში დაამატეთ ID, გზა,
   რედაქტორისთვის გასაგები სახელი და ორიგინალური ზომები. SVG არჩევანი ავტომატურად
   გამოჩნდება არსებულ რეგისტრირებულ SVG კომპონენტში.
2. ახალი React კომპონენტისთვის `component-registry.ts`-ში დაამატეთ უნიკალური
   ID/ვერსია, მკაცრი Zod სქემა, ქართული სახელი, `kind` და ხელმისაწვდომობის კონტრაქტი.
   გამოიყენეთ მხოლოდ მონაცემები; არ მიიღოთ module path, JSX ან ფუნქცია შიგთავსიდან.
   თუ კომპონენტი სურათს იყენებს, დეველოპერის `imageAssets(props)` კონტრაქტმა უნდა
   დააბრუნოს ყველა სტატიკური/მედიის მისამართი. ასე მოწმდება ფაილის/მედიის არსებობა
   და იწერება რევიზიის მედია-კავშირები. ეს ფუნქცია რეგისტრის კოდშია, არა სტატიაში.
3. `components/articles/document-renderer.tsx`-ში მიაბით ID სტატიკურ import-ს.
   ინტერაქტიულ ვიზუალს დაურთეთ იზოლირებული შეცდომის საზღვარი და ტექსტური/ცხრილური
   fallback, როგორც არსებულ `InteractiveVisual`-შია. ახალი ID თავისით არ სრულდება.
4. `ArticleDocumentEditor`-ში დაამატეთ შესაბამისი მეგობრული ველები და
   `ArticleVisualPreview`/ავტორიზებულ `previewArticleVisual`-ში შესაბამისი პრევიუ.
   რედაქტორმა properties კოდით არ უნდა შეავსოს. SVG გრაფიკის ახალი asset-ისთვის
   დამატებითი property-რედაქტორი საჭირო არ არის.
5. შეამოწმეთ სქემა, asset-ების ბმულები, წყაროები, accessibility fallback და
   desktop/tablet/mobile გეომეტრია. ძველი კომპონენტის კონტრაქტის შეცვლისას გაზარდეთ
   ვერსია და შეინარჩუნეთ ძველი ვერსიის რენდერერი ისტორიული სტატიებისთვის.

ისტორიული კატალოგი `scripts/article-foundation/archive/`-ში მხოლოდ აღდგენისა და
მიგრაციის მტკიცებულებაა. ახალ სტატიას იქ ნუ დაამატებთ: ერთადერთი საჯარო წყარო
არის ბაზის ვალიდური გამოქვეყნებული რევიზია.
